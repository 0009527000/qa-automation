# AI 辅助生成测试用例 · Prompt 模板

> 这是**模板**，仓库里没有任何已生成的真实统计数据。跑完之后把结果记到 `review.md`。

## 用法

1. 把被测接口的文档（路径、方法、参数、响应示例、业务规则）粘到下面 `{{API_DOC}}` 的位置。
2. 调用任意大模型，拿到 YAML 输出。
3. **逐条人工评审**：能跑、断言正确、覆盖点不重复 → 采纳（`cases/` 里 `source` 标为 `ai`）；幻觉字段、路径不存在、断言含糊 → 拒绝并记原因。
4. 统计采纳率，并把被拒绝样例、AI 漏掉的场景写进 `review.md`。

## Prompt

```
你是软件测试工程师。根据下面的接口文档，用等价类划分、边界值分析、
异常场景（空值 / 超长 / 类型错误 / 越权 / 状态异常）设计测试用例。

输出要求：
- 只输出 YAML，不要任何解释文字；
- 顶层为 cases 列表，每条包含：
  id、name、method、path、body、params、expect(status 与 json 字段)、tags、覆盖点说明；
- id 以 TC_模块_序号 命名，不要与已有用例重复；
- 断言必须能被程序直接校验，不要写「返回正常」「符合预期」这类模糊描述。

接口文档：
{{API_DOC}}
```

## 评审时重点看什么

- **幻觉**：编造不存在的字段、路径、错误码 → 拒绝。
- **漏测**：并发、权限、状态流转、幂等、依赖数据缺失 → 记到漏测清单，人工补。
- **重复**：与手工用例覆盖点相同的 → 合并，别虚增用例数。
- **可执行性**：body / params 是否符合真实接口契约。
